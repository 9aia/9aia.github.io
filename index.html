The Stack

One organism, four layers: delivery down to interface.

Delivery

How artifacts and state move: packs install, releases ship, the gate guards pushes, the substrate syncs.

  • tamiasThe entrypoint: fetch, store, cache, dispense
  • hyphaDistributed substrate: entities across machines
  • scarabConfig loading & templated content packs
  • tarsiThe release plane: changelog to publish
  • buphaThe gate: CI as tamias bundles
Memory

What persists as knowledge: the work ledger and the verified code maps.

  • mycoThe ledger: durable work memory
  • kudaRepo memory: verified code maps
Process

How work is governed and run: coordination, secrets, verification, schedules, sessions, campaigns.

  • mimusThe critic: claims verified against code
  • sturnThe WAL: coordination in milliseconds
  • cuoraSecrets broker: sealed, not spilled
  • sepiaSession lifecycle: agents, agnostically
  • lasiusGit & workspace expertise
  • cicadaCalendars as code: scheduled work
  • peregrinCampaigns: event-driven orchestration
Interface

What renders for humans and agents: every view the drivers emit.

  • pavoThe screen: renders every view

Why GAIA

The missing layers between coding agents and the repositories they work on.

We're building the missing layers between coding agents and the repositories they work on: delivery (tamias, scarab, tarsi, bupha, hypha), memory (myco, kuda), process (sturn, cuora, mimus, cicada, lasius, sepia, peregrin), and interface (pavo). Open, minimal, composable. A stack agents can actually run on.
